# Laboratorio Virtual de Ciencias Naturales

Aplicación web interactiva para estudiantes colombianos de **6.º a 11.º**. Cada práctica permite preparar el experimento, cambiar variables, ejecutar ensayos, registrar datos, graficarlos, analizar su tendencia, concluir con evidencia y responder preguntas por competencias con retroalimentación formativa.

Los resultados se **calculan con modelos científicos explícitos** (ecuaciones y reglas documentadas, con supuestos y límites). No hay resultados aleatorios sin justificación: el único azar es el de la segregación genética en la práctica de Mendel, con semilla reproducible.

> Simulación educativa: no reemplaza el laboratorio real. Las preguntas tipo Saber 11 son **originales** de esta plataforma y **no son preguntas oficiales del ICFES**. Las relaciones con estándares y DBA son paráfrasis y propuestas que el docente debe validar con los documentos oficiales.

## Ejecutar

Requisitos: Node.js 22.13 o superior.

```bash
npm install
npm run dev          # servidor de desarrollo: http://localhost:5173
npm run build        # versión de producción en dist/ (servible como sitio estático)
npm run preview      # sirve dist/ en http://localhost:4173
npm run build:single # un único archivo dist-single/laboratorio.html (funciona sin servidor, con doble clic)
```

Pruebas:

```bash
npm test             # pruebas unitarias (Vitest): fórmulas, currículo, utilidades
npm run test:e2e     # interfaz, servidor real y auditoría de accesibilidad WCAG 2.1 AA (Playwright + axe-core)
npm run server       # servidor institucional opcional (ver server/README.md)
```

Si Chromium ya está instalado en otra ruta: `PW_CHROMIUM_PATH=/ruta/a/chrome npm run test:e2e`.

No requiere servicios de pago, cuentas ni base de datos. Las fuentes tipográficas vienen incluidas en la aplicación (no se consulta a Google ni a otros terceros).

## Sin conexión e instalable

Después de la primera visita con internet, la aplicación completa queda guardada en el navegador (service worker generado en la compilación por `scripts/build-sw.mjs`) y todas las prácticas abren sin conexión. Se puede instalar como aplicación en Windows, Android, iPhone y Chromebook (botón «Instalar la aplicación» en el inicio y en Ayuda). Cuando se publica una versión nueva aparece un aviso para actualizar; el trabajo guardado se conserva. Enviar informes al servidor sí requiere conexión.

## Guías de trabajo en PDF

```bash
npm run guias        # requiere Python 3 con reportlab y la fuente DejaVu Sans
```

Genera en `guias-pdf/` (carpeta no versionada), para cada práctica, la **guía del estudiante** (`estudiante/guia-<grado>-<id>.pdf`) con el formato institucional de la I.E. Campo Alegre: encabezado, identificación, código QR que abre la práctica, objetivos y DBA (propuesta), introducción, hipótesis y variables, procedimiento, tabla de datos, cuadrícula para graficar, análisis y conclusión, evaluación por competencias, aplicación, rúbrica por niveles y observaciones; y la **clave del docente** (`docente/clave-<grado>-<id>.pdf`) con respuestas justificadas, errores frecuentes, ecuaciones, supuestos y límites del modelo. El logo institucional se toma de `scripts/guias/assets/LOGO_COLEGIOS.png`.

## Evaluación

En las preguntas de selección múltiple, la posición de la respuesta correcta se reparte entre A, B, C y D de forma estable (`src/assessment/balance.ts`), para que marcar siempre la misma letra no dé ventaja.

## Cómo agregar una práctica

1. Escribe el modelo en `src/models/mi-modelo.ts` (funciones puras con validación de rangos) y su `ModelSpec`.
2. Agrega pruebas en `tests/unit/mi-modelo.test.ts`.
3. Define las columnas de la tabla en `src/labs/datasets.ts` (marca con `input: true` las variables que controla el estudiante).
4. Crea el componente `src/labs/MiLab.tsx` (recibe `api` y llama `api.addTrial(datasetId, valores)`), y regístralo en `src/labs/registry.ts`.
5. Escribe el contenido en `src/curriculum/practices/mi-practica.ts` (estructura `PracticeDef`), agrégalo a `PRACTICES` en `src/curriculum/index.ts` y a `LOADERS` en `src/curriculum/loader.ts`, y regenera el catálogo liviano con `node scripts/gen-catalog.mjs`.
6. Si la práctica tiene variables numéricas para analizar, decláralas en `relations` (variable x, variable y y conjunto de datos); es opcional. Las pruebas de `tests/unit/curriculum.test.ts` comprobarán que la práctica tiene todas las secciones y que sus relaciones apuntan a columnas numéricas existentes.

## Almacenamiento, panel docente y servidor opcional

- El trabajo de cada estudiante se guarda en el almacenamiento local de su navegador.
- **Sin servidor:** el estudiante entrega su informe como archivo `.json` o texto copiado y el docente lo importa en el panel docente. Asignaciones y listas se comparten con códigos (`LVCN-A:` / `LVCN-L:`).
- **Con servidor** (opcional, `server/`): el docente crea su cuenta y sus cursos; el estudiante envía su informe con el código de 6 caracteres del curso, sin crear cuenta; el docente lo descarga en la pestaña **Servidor**. Instalación, seguridad y protección de datos en [server/README.md](server/README.md).
- **Seguimiento del curso** (con servidor): el estudiante se une con «Unirme a mi curso» (código + nombre + PIN de 4 dígitos) y su avance se sincroniza solo; el docente lo ve en la pestaña **Seguimiento del curso**.

| Modo | Dónde quedan los datos | Qué ve el docente | Cómo llega |
|---|---|---|---|
| Sin servidor | Navegador del estudiante (`localStorage`) | Informes que importa en **Informes** | Archivo `.json` o texto copiado |
| Servidor · informe | Servidor del colegio (SQLite) | Informes en **Servidor → Traer informes** | El estudiante pulsa «Enviar informe» con el código del curso |
| Servidor · seguimiento | Servidor del colegio (SQLite) + cola local sin conexión | Inscritos, activos hoy y en 7 días, ingresos por día, mapa de calor estudiantes × prácticas, detalle por estudiante (etapas, datos, conclusión, respuestas, línea de tiempo), análisis por pregunta y competencia, alertas y CSV | Automático: resumen de cada práctica con antirrebote; si no hay red, se envía al volver |

- **Validación curricular:** pestaña del panel docente para registrar, por práctica, el DBA y el estándar verificados en los documentos oficiales, exportable para el equipo de área.
- **Moodle y Google Classroom:** pestaña del panel docente que exporta, sin servidor, las preguntas del banco Saber 11 y de las prácticas en Moodle XML o GIFT (filtradas por práctica, grado y área, con la respuesta correcta y la retroalimentación), y por práctica el enlace oficial «Compartir en Classroom», el texto de la tarea y un CSV de enlaces por grado. Guía paso a paso y límites en [docs/EXPORTAR-LMS.md](docs/EXPORTAR-LMS.md).
- **Usabilidad:** cada práctica incluye una encuesta breve de opinión que viaja en el informe; el protocolo para pruebas con estudiantes está en [docs/PROTOCOLO-USABILIDAD.md](docs/PROTOCOLO-USABILIDAD.md).

## Interfaz y sistema de diseño

La interfaz (rediseño 2.6.0, [ADR 0007](docs/v2/adr/0007-sistema-de-diseno-y-espacio-de-trabajo.md)) se organiza por
tareas y alrededor del espacio de trabajo de cada práctica:

- **Inicio por perfil**: estudiante, docente o investigador/curioso; cada perfil muestra cuatro tareas («Continuar mi
  práctica», «Asignar una práctica», «Prácticas de indagación»…), luego grados, asignaturas y una práctica por grado.
- **Catálogo** con búsqueda (tecla `/`), filtros por grado, asignatura, competencia y avance, orden, chips de filtros
  activos y filtros en la dirección para compartir (`#/catalogo?area=quimica&grado=10`).
- **Práctica**: encabezado compacto con migas (grado y área), barra de etapas fija, paso del procedimiento, una sola
  franja de ajustes del instrumento (medición ideal/real, modo avanzado, procedencia), laboratorio, cuaderno de datos y
  navegación a la práctica anterior y siguiente del grado.
- **Componentes experimentales compartidos**: barra de simulación iniciar/pausar/reanudar/reiniciar con estado y avance,
  avisos de condición no válida con causa y cómo corregirla, lecturas con unidad, resolución y estado, explicación de la
  relación entre variables a partir de los datos, comparación de ensayos y exportación CSV, JSON (`lvcn-datos-v1`), PNG y
  SVG.
- **Atajos de teclado**: `?` (lista), `/` (buscar), `1`–`5` (etapas), `C` (cuaderno), `F` (pantalla completa), `I`
  (informe), `N`/`P` (práctica siguiente/anterior). Se desactivan en «Ayuda y accesibilidad».
- **Sistema de diseño** en [docs/v2/SISTEMA-DE-DISENO.md](docs/v2/SISTEMA-DE-DISENO.md): tokens en `src/tokens.css`
  (primario institucional azul petróleo, secundario pizarra, semánticos, escala de 8 series de datos distinguible con
  daltonismo, tipografía modular, espaciado, radios, elevación, movimiento), capas `styles.css` → `theme-2026.css` →
  `plataforma.css`, y verificación de contraste con `python3 scripts/diseno/verificar_paleta.py`.

## Accesibilidad

Navegación completa por teclado (incluidas flechas en las pestañas), enlace «Saltar al contenido», foco visible, etiquetas en todos los controles, regiones `aria-live` para resultados, descripciones textuales y tabla equivalente para cada gráfica, tema claro/oscuro, alto contraste, tamaño de texto ajustable, reducción de animaciones, diseño adaptable desde 360 px y fuente Atkinson Hyperlegible. Las series de las gráficas se distinguen por color (verificado con simulación de daltonismo) y por la forma del marcador; los estados se dicen en texto. Una auditoría automática con axe-core (WCAG 2.2 A/AA) recorre todas las páginas y prácticas en tema claro, oscuro y en teléfono.
